# AGENTS.md — Instructions for AI Coding Agents

## Project overview

`mcsr-kb` is a public knowledge base of Minecraft 1.16.1 game mechanics for speedrunners. Content is generated by analyzing the decompiled source at `./mc1.16.1/` (gitignored) and writing structured Markdown articles.

## Article authoring workflow

1. Identify the relevant Java class(es) in `mc1.16.1/src/` for the mechanic being documented.
2. Read and analyze the relevant methods — focus on conditions, branches, and constants.
3. Write a KB article following the schema in `schemas/article.schema.json`.
4. Register the article in `kb/index.md`.

**Never commit**:
- Raw Java source excerpts or snippets longer than a single method signature
- Anything from `mc1.16.1/`
- Decompiler output in any form

## KB article conventions

### Frontmatter (required)

```yaml
---
title: <descriptive title>
topic: worldgen | entities | rng | physics | mechanics
subtopic: <optional>
tags: [snake_case, keywords]
source_classes:
  - net.minecraft.fully.qualified.ClassName
mc_version: 1.16.1
summary: "<one sentence direct answer — the most important field>"
---
```

### Body structure

Use this section order (omit sections that don't apply):

1. **Overview** — 2–4 sentences expanding the summary
2. **Conditions / Rules** — bulleted list; use plain English, not Java
3. **Step-by-step logic** — numbered list for sequential processes
4. **Constants and values** — table of magic numbers, ranges, probabilities
5. **Edge cases** — unusual inputs or boundary conditions
6. **Speedrun relevance** — what this means for routing or manipulation
7. **Caveats** — obfuscation gaps, unconfirmed behavior, version caveats
8. **Source classes** — prose explanation of which classes to read for more detail

### Style rules

- Describe *behavior*, not code. "The game picks a random angle" not "Math.nextFloat() is called."
- You may name a class to establish credibility: "StrongholdStructure places strongholds in rings."
- Use speedrunning vocabulary: seed, RNG manipulation, cycle, tick, etc.
- Tables for numeric constants (distances, probabilities, counts).
- Bold key terms on first use.

## Adding a new article

```
kb/<topic>/<descriptive-slug>.md
```

Then add a line to `kb/index.md` under the appropriate section:

```
| [Title](./topic/slug.md) | one-sentence summary | stub \| partial \| complete |
```

## Answering questions with this KB

### Directory structure

| Path | Contents |
|---|---|
| `kb/index.md` | Master topic index; start here for discovery |
| `kb/worldgen/` | Structure placement (strongholds, fortresses, bastions, villages) and terrain |
| `kb/entities/` | Mob AI, aggression conditions, targeting, pathfinding |
| `kb/rng/` | Java `Random` mechanics, seed derivation, manipulable RNG chains |
| `kb/physics/` | Player velocity, collision, water/lava movement, elytra |
| `kb/mechanics/` | Portal linking, loot tables, enchanting, fire resistance, etc. |

### How to answer a user question

1. **Check `kb/index.md`** for the relevant topic. Each entry links to the article and shows its `summary`.
2. **Read the linked article**. The `summary` field answers the question at a glance; the article body provides conditions, edge cases, and implementation details.
3. **Translate to plain language**. Users are speedrunners, not Java programmers — describe behavior, not code. You may name the source class (e.g., "according to `StrongholdStructure`") to establish credibility, but do not quote Java.
4. **Fill gaps**. If no article exists for the topic, do not just flag it — research and create it first. Find the relevant class(es) in `mc1.16.1/src/`, follow the Article authoring workflow above, write the article, register it in `kb/index.md`, then answer the question from the new article. Do not invent mechanics.

### Confidence and version notes

- All articles are pinned to **1.16.1**. Behavior in other versions may differ.
- Where article confidence is partial (e.g., a field was obfuscated), the article body notes it explicitly under a **Caveats** section.
- If an article's `mc_version` does not match the version being asked about, state the version mismatch before answering.

### What this KB does not cover

- Bedrock Edition (different codebase)
- Versions other than 1.16.1 (unless a `mc_version` field says otherwise)
- Subjective routing decisions (use community resources for those)
- Mods or external tools
